¿Qué es y para qué sirve?

El conector AWS S3 permite que el agente de Ruvic gestione objetos en un bucket específico de Amazon S3. Una vez configurado, puedes pedirle al agente cosas como:

  • “Sube este reporte al bucket con el nombre reportes/julio-2026.csv.”
  • “¿Qué archivos hay en la carpeta facturas/ del bucket?”
  • “Genérame un enlace para descargar el archivo contrato.pdf que dure 1 hora.”

Operaciones soportadas:

Operación Qué hace
s3.list_objects Lista los objetos del bucket, con filtro por prefijo
s3.upload Sube (o sobrescribe) contenido en una clave del bucket
s3.download Descarga el contenido de un objeto
s3.presigned_url Genera una URL de acceso temporal, sin exponer credenciales
Este conector escribe s3.upload sobrescribe el objeto de la clave indicada. El conector opera sobre un único bucket; se recomienda que la policy IAM del usuario esté limitada a ese bucket específico.

Prerrequisitos

  • Una cuenta de AWS con un bucket S3 ya creado.
  • Acceso a la consola de IAM para crear un usuario y su policy, solo durante la configuración inicial.
  • El nombre del bucket y la región de AWS donde está creado (ej. us-east-1).

Configuración en el fabricante

Vas a crear un usuario IAM dedicado para Ruvic, con una policy limitada al bucket que quieres exponer. No reutilices credenciales root ni las de otra aplicación.

  1. Crea la policy limitada al bucket.

    En IAM → Policies → Create policy → pestaña JSON, reemplazando mi-bucket-produccion por el nombre real de tu bucket:

    {
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::mi-bucket-produccion"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:PutObject"],
      "Resource": "arn:aws:s3:::mi-bucket-produccion/*"
    }
  ]
}
  2. Crea el usuario IAM y adjunta la policy.

    En IAM → Users → Create user → marca "Provide user access to the AWS Management Console" en NO (es un usuario programático) → adjunta la policy creada en el paso 1.

    [ Captura: creación de usuario IAM con la policy adjunta — reemplazar por assets/img/s3-iam-user.png ]
  3. Genera las claves de acceso.

    En la página del usuario → pestaña "Security credentials" → "Create access key" → tipo "Application running outside AWS". Copia el Access Key ID y el Secret Access Key (este último solo se muestra una vez): los usarás en el formulario de Ruvic.

  4. Verifica el acceso desde la línea de comandos.

    Con el AWS CLI configurado con esas credenciales:

    aws s3 ls s3://mi-bucket-produccion --region us-east-1

    Si responde sin error (aunque el bucket esté vacío), el fabricante quedó listo. Anota estos valores para la siguiente sección: Access Key ID, Secret Access Key, región y nombre del bucket.

Permisos requeridos

Principio de mínimo privilegio: el usuario de Ruvic solo necesita estos permisos, limitados al bucket configurado. No otorgues s3:*, s3:DeleteBucket, s3:PutBucketPolicy ni acceso a otros buckets.

Permiso Para qué sirve
s3:ListBucket (sobre el bucket) Listar objetos (s3.list_objects)
s3:GetObject (sobre los objetos) Descargar objetos y generar URLs de descarga (s3.download, s3.presigned_url)
s3:PutObject (sobre los objetos) Subir objetos y generar URLs de subida (s3.upload, s3.presigned_url)

Configuración en Ruvic

Entra a Settings → Conectores, busca la tarjeta AWS S3 y pulsa Configurar. Diligencia el formulario con los valores que obtuviste en la sección anterior:

Campo del formulario Valor
Access Key ID El Access Key ID del paso 3
Secret Access Key El Secret Access Key del paso 3. Se guarda cifrado como secreto: la interfaz no volverá a mostrarlo
Región de AWS La región donde está creado el bucket (ej. us-east-1)
Bucket Nombre del bucket configurado en la policy del paso 1
Timeout de conexión Opcional; 10 segundos por defecto

Guarda y pulsa Probar conexión — la plataforma verificará el acceso al bucket configurado.

[ Captura: formulario del conector AWS S3 en Settings → Conectores — reemplazar por assets/img/s3-form.png ]

Verificación

  1. Test de conexión exitoso.

    El botón Probar conexión debe responder: “Conexión exitosa al bucket 'mi-bucket-produccion' en us-east-1”. La tarjeta del conector cambia a estado Configurado.

  2. Automatización mínima de prueba.

    Abre una conversación nueva con el agente y pídele: “Sube un archivo de prueba al bucket con el texto 'hola mundo' y luego dime qué archivos hay.” El agente debe subir el objeto y listarlo de vuelta. Si lo hace, el conector quedó operativo de punta a punta.

Solución de problemas

Mensaje / síntoma Causa probable y solución
“Credenciales inválidas o sin permiso IAM suficiente” Access Key o Secret Key mal copiados, o la policy no incluye los permisos necesarios sobre ese bucket. Reintenta los pasos 1 y 3 de la sección 3.
“No se pudo conectar al servicio S3 … (timeout)” La región configurada no coincide con la región real del bucket, o hay un problema de red saliente hacia AWS. Verifica la región con aws s3api get-bucket-location --bucket tu-bucket.
“El bucket no existe o no es accesible” Nombre de bucket mal escrito en el formulario, o la policy IAM apunta a un ARN distinto. Verifica que el ARN de la policy coincida exactamente con el nombre del bucket.
El agente lista objetos pero falla al descargar uno Falta s3:GetObject en la policy, o la clave del objeto tiene mayúsculas/espacios distintos a los mostrados (S3 distingue mayúsculas de minúsculas).
El conector aparece “Sin configurar” tras guardar Algún campo obligatorio quedó vacío. Ábrelo de nuevo y completa Access Key ID, Secret Access Key, región y bucket.

Preguntas frecuentes y notas de seguridad

¿El agente puede acceder a otros buckets de mi cuenta?

No, si la policy IAM está correctamente limitada (ver sección 3) — el Resource de la policy apunta a un solo bucket. Si usas una policy más amplia (ej. "Resource": "*"), el conector técnicamente podría acceder a otros buckets, aunque en la práctica solo opera sobre el bucket configurado en el formulario.

¿Dónde queda guardado el Secret Access Key?

Como secreto en el almacén de credenciales de la plataforma, asociado a tu usuario. La interfaz nunca vuelve a mostrarlo; solo indica “definida”. Para cambiarlo, escribe uno nuevo en el formulario; para conservarlo al editar otros campos, deja el campo vacío.

Rotación de credenciales

Recomendado cada 90 días o según tu política: genera un nuevo Access Key en IAM → Security credentials, actualízalo en el formulario del conector, prueba la conexión, y luego desactiva/elimina la clave anterior desde la consola de AWS.

¿Qué hago si las credenciales se comprometen?

  1. Desactiva o elimina el Access Key de inmediato en IAM → Security credentials.
  2. Revisa la actividad reciente en AWS CloudTrail para ese usuario.
  3. Genera un Access Key nuevo y actualízalo en el formulario del conector.

¿Expiran las credenciales?

Por defecto no (las Access Keys de IAM no expiran solas). Si tu organización exige rotación forzosa, puedes configurar una política de IAM con antigüedad máxima y recibirás alertas para rotarlas manualmente.

Buenas prácticas Usa siempre un usuario IAM dedicado con policy limitada a un único bucket; nunca uses las credenciales root de la cuenta de AWS; prefiere URLs prefirmadas en vez de compartir archivos descargados manualmente; y evita compartir el Secret Access Key por canales no seguros.
